Offline queue and sync

Inspectors work in godowns, basements and rural markets. A tool that needs a network round-trip to give a verdict is useless exactly where it is needed most — so every scan is decided entirely on this device and written to a local queue. A background thread drains the queue whenever the link comes back. Switch the device offline below, run a few scans, and watch the two databases diverge and then reconcile.

How this is wired

The device writes to data/atlas.db; the departmental server is data/central.db. The transfer is a local database write rather than an HTTP call, which keeps the whole system runnable with no network. Swapping one function for a POST to a real endpoint is the only change a deployment needs.
